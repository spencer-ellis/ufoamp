Matrix elements straight
from a UFO model.

ufoamp evaluates tree-level helicity amplitudes and |M|² by reading a UFO model directly, with coupling values chosen at run time — no code generation, no recompilation. Changing CV, C2V, C3, or switching from the SM UFO to HHVBF, is a function call.

Quick start View on GitHub Manual (PDF)

Why it exists

Built for the VBF di-Higgs and Goldstone-equivalence studies, where every question is “what happens to this amplitude when I change that coupling?”

No code generation

Berends–Giele recursion

Currents are built straight from the UFO vertex table, so no diagrams are enumerated and nothing is written to disk or compiled. New model, new process, same code path.

Run-time couplings

Reweighting is a function call

set_param({"C2V": 0}) re-derives every internal parameter and coupling consistently. Scans and per-event reweighting need one matrix element, not one build per point.

Cross-checked

MadGraph standalone built in

ufoamp.mg5ref generates and compiles MG5’s C++ for the same process and compares on identical points, symmetry factors handled — machine precision on eight SM processes.

Quick start

Install, then point it at a UFO directory. momenta are NumPy 4-vectors [E, px, py, pz] with metric (+−−−), ordered initial + final.

pip install git+https://github.com/spencer-ellis/ufoamp.git
# or, from a clone:  pip install -e .        (optional extras: pip install "ufoamp[jax]")
|M|² for u d → u d H H at a chosen coupling point
from ufoamp.analysis import MatrixElement

me = MatrixElement("HHVBF_UFO", "u d > u d h h",
                   couplings={"CV": 1, "C2V": 2, "C3": 1},
                   max_orders={"QCD": 0})       # MadGraph's QCD=0

me.m2(momenta)                                  # spin/colour summed, initial averaged
me.m2_events(events, n_jobs=8)                  # (N, n, 4) -> (N,)
me.set_param({"C2V": 0})                        # switch hypothesis, no rebuild
me.helicity_amplitudes(momenta)                 # {(h1,...,hn): M}
Polarisations, LHE samples, and the validation ladder
w = MatrixElement("HHVBF_UFO", "w+ w- > h h", couplings={"CV": 1, "C2V": 1, "C3": 1})
w.m2(momenta, pol={"w+": "L"})                  # external helicity selection
w.m2_polarized(momenta, ["w+", "w-"])           # {'LL','LT','TL','TT'}, sums to the total

from ufoamp.analysis import SampleEvaluator, read_lhe
ev = SampleEvaluator("HHVBF_UFO", couplings={"CV": 1, "C2V": 1, "C3": 1})
ev.m2_sample(read_lhe("events.lhe.gz"))         # mixed-flavour p p > ... samples
# every line of the ladder must say PASS
export UFOAMP_MODELS=/path/to/models   # SM_UFO/, HHVBF_UFO/, SMEFTsim/UFO_models/
./run_tests.sh

# capability report + MadGraph comparison for any model/process
python3 -m ufoamp.validate --model /path/UFO --process "u d > u d h h" \
        --orders QCD=0 --mg5 /path/mg5amcnlo --mg5-model HHVBF_UFO

What it handles

Everything below is exercised by the test ladder in the repository.

Lorentz & colour

General UFO structures

Any UFO Lorentz string (Metric, P, Gamma, ProjM/P, Identity, Gamma5, Epsilon, Sigma, atom powers) and every colour structure (T, f, d, Identity, Epsilon) become one compiled einsum. Colour sextets are not supported.

Polarisation

External and internal

External helicities in a chosen frame (pol_frame: lab, partonic CM, or any leg set), plus an exact propagator decomposition −gμν + kμkν/M² = T + L + S for the t-channel fusing bosons.

Gauge

Feynman or unitary

Auto-detected from whether the UFO ships Goldstones, and forceable. Feynman ≡ unitary is verified numerically on WLWL → HH and VBF-HH.

SMEFT

SMEFTsim 3, all nine variants

Wilson coefficients are ordinary overrides. 5- and 6-leg vertices, four-fermion operators with Fierz-crossed chains, and the GF input-scheme shifts are reproduced.

Fermions

Majorana and clashing arrows

Charge conjugation in place for fermion-flow-violating vertices, validated against MG5 on MSSM_SLHA2 at 1e-14–1e-16, including negative SLHA mass eigenvalues.

Differentiable

JAX backend

JaxMatrixElement traces UFO parameters → couplings → |M|² once and compiles it: grad_params, grad_momenta and hessian_params, matching NumPy to machine precision.

Speed

Events and helicity configurations share one pass of the recursion, with a batch axis on every wavefunction, current and propagator, and exactly-vanishing helicity configurations pruned. Per core: about 0.1 ms for 2 → 2, 1.6 ms per VBF-HH event, and 20 ms for u d > u d z z h. Colour cost scales as 8#gluons, so up to four gluons is comfortable and gg → ggg is not.

A physics result worth knowing before you scan CV

The HHVBF UFO scales only the physical VVH (CV), VVHH (C2V) and HHH (C3) vertices; every Goldstone–Higgs vertex keeps its SM value. So in Feynman gauge the O(s) growth of WLWL → HH goes like (C2V − 1), independent of CV, while in unitary gauge — MadGraph’s default — it goes like (C2V − CV²).

The two agree only at CV = 1. Away from CV = 1 the model is gauge dependent, so MadGraph and RECOLA disagree there. C2V and C3 scans at CV = 1 are safe.

What is inside

About 3 700 lines of Python, no build step, no generated code.

ModuleRole
ufo_model.pyself-contained UFO loader, modern and legacy (never imports the UFO’s own library)
couplings.pyparameters → couplings, with run-time overrides and injected derived values
dirac.py, wavefunctions.py, propagators.pyfrozen conventions: metric, Dirac basis, helicity spinors, polarisation vectors, propagators
vertex_eval.pygeneral einsum evaluator: any UFO Lorentz string → off-shell current
recursion.pyBerends–Giele recursion driven by the vertex table; fermion-line connectivity gives exchange signs and colour flow
process.py, analysis.pyuser interface: process strings, |M|², polarisation selection, event arrays, LHE reader
jaxme.pycompiled, differentiable matrix elements
mg5ref.pyMadGraph standalone reference: generate, compile, compare
phasespace.py, validate.pyRAMBO; capability report and the ufoamp-validate command

Not yet supported

Spin-2 particles, colour sextets, and custom propagators or form factors.
